# Especificação JSON do Mercado de Plugins do AstrBot

Versão da especificação: 2026-06-27

Versão do esquema JSON do mercado: 1

## 1. Escopo

Este documento define o formato JSON das fontes do mercado de plugins do AstrBot.

## 2. Termos

- `PluginRecord`: uma entrada de plugin em uma fonte do mercado.
- `MarketMetadata`: metadados da própria fonte do mercado.
- `plugin_id`: identificador global do pacote do plugin.
- `metadata.yaml`: arquivo de metadados do plugin dentro do pacote instalado.

Os termos normativos `MUST`, `MUST NOT`, `SHOULD`, `SHOULD NOT` e `MAY` correspondem, respectivamente, a **DEVE**, **NÃO DEVE**, **RECOMENDA-SE**, **NÃO SE RECOMENDA** e **PODE**.

## 3. Formato do documento

Uma fonte do mercado de plugins DEVE ser um objeto JSON codificado em UTF-8.

O objeto raiz DEVE conter a chave reservada `$meta`.

Todas as chaves do objeto raiz, exceto `$meta`, DEVEM ser uma destas opções:

- uma string `plugin_id`
- uma string `name`, conforme a exceção de compatibilidade da Seção 5

Cada chave do objeto raiz, exceto `$meta`, DEVE corresponder a um objeto `PluginRecord`:

```json
{
  "$meta": {
    "schema_version": 1,
    "name": "Mercado oficial de plugins do AstrBot",
    "version": "2026-06-27",
    "homepage": "https://astrbot.app",
    "repository": "https://github.com/AstrBotDevs/AstrBot_Plugins_Collection"
  },
  "owner/astrbot_plugin_foo": {
    "author": "owner",
    "name": "astrbot_plugin_foo",
    "version": "1.0.0",
    "repo": "https://github.com/owner/astrbot_plugin_foo",
    "desc": "Descrição do plugin"
  },
  "astrbot_plugin_bar": {
    "author": "owner",
    "version": "1.0.0",
    "repo": "https://github.com/owner/astrbot_plugin_bar",
    "desc": "Registro de compatibilidade que usa a chave raiz como nome"
  }
}
```

O objeto raiz NÃO DEVE conter campos de metadados de nível superior fora de `$meta`.

## 4. Metadados do mercado

`$meta` NÃO DEVE ser interpretado como um `PluginRecord`.

`$meta` DEVE ser um objeto `MarketMetadata`.

`MarketMetadata` DEVE conter:

| Campo            | Tipo    | Requisito                                                                |
| ---------------- | ------- | ------------------------------------------------------------------------ |
| `schema_version` | integer | Versão do esquema JSON do mercado. DEVE ser `1` para esta especificação. |

`MarketMetadata` PODE conter:

| Campo         | Tipo   | Requisito                                                                 |
| ------------- | ------ | ------------------------------------------------------------------------- |
| `name`        | string | Nome legível da fonte do mercado.                                         |
| `version`     | string | Versão dos dados da fonte do mercado. NÃO DEVE ser usada como versão do esquema. |
| `homepage`    | string | URL HTTPS da página inicial.                                              |
| `repository`  | string | URL HTTPS do repositório dos dados da fonte do mercado.                   |
| `description` | string | Descrição da fonte do mercado.                                            |
| `updated_at`  | string | Data e hora no formato ISO 8601.                                          |

`$meta` NÃO DEVE ser usado para:

- identidade do plugin
- resolução da fonte de instalação
- resolução da fonte de atualização
- validação de segurança do plugin

## 5. Identidade do plugin

`plugin_id` é definido como:

```text
metadata.author + "/" + metadata.name
```

Para cada `PluginRecord`:

- Recomenda-se que a chave raiz seja igual a `${author}/${name}`.
- A chave raiz PODE ser igual a `name` conforme a exceção de compatibilidade abaixo.
- `author` DEVE ser igual a `metadata.yaml.author`.
- `name` DEVE ser igual a `metadata.yaml.name`.
- `plugin_id` DEVE ser globalmente exclusivo em todo o ecossistema de plugins do AstrBot.
- Dois valores de `plugin_id` que sejam iguais após a normalização para minúsculas NÃO DEVEM coexistir.
- `repo` NÃO DEVE ser usado como identidade do plugin.
- `root_dir_name`, nomes de diretórios locais, nomes de exibição e nomes de registro NÃO DEVEM ser usados como identidade do plugin.

`author` e `name`:

- DEVEM ser strings não vazias.
- DEVEM estar sem espaços em branco nas extremidades.
- NÃO DEVEM conter `/`.
- NÃO DEVEM conter caracteres de controle ASCII.
- Recomenda-se que sejam valores estáveis de identidade do pacote, e não nomes de exibição.

### 5.1. Exceção de compatibilidade para a chave `name`

Uma chave raiz PODE ser igual a `metadata.yaml.name` em vez de `${author}/${name}`.

Quando essa exceção for usada:

- A chave raiz NÃO DEVE conter `/`.
- `author` DEVE estar presente.
- `name` PODE ser omitido.
- Se `name` estiver presente, DEVE ser igual à chave raiz.
- A chave raiz DEVE ser igual a `metadata.yaml.name`.
- Os consumidores DEVEM construir `plugin_id` como `${author}/${root_key}`.

## 6. Campos obrigatórios

Cada `PluginRecord` DEVE conter:

| Campo     | Tipo   | Requisito                                                                                                                        |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `author`  | string | Namespace do autor do plugin. DEVE corresponder a `metadata.yaml.author`.                                                        |
| `name`    | string | Nome do pacote do plugin. DEVE corresponder a `metadata.yaml.name`. PODE ser omitido somente quando a chave raiz for igual a `metadata.yaml.name`. |
| `version` | string | Versão do plugin. DEVE corresponder a `metadata.yaml.version`.                                                                   |
| `repo`    | string | URL HTTPS de um repositório GitHub usada para atribuição da origem e instalação.                                                 |
| `desc`    | string | Descrição padrão do plugin.                                                                                                      |

## 7. Campos opcionais

| Campo               | Tipo     | Requisito                                                                                  |
| ------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `display_name`      | string   | Nome legível do plugin.                                                                    |
| `short_desc`        | string   | Descrição curta para interfaces compactas.                                                 |
| `download_url`      | string   | URL HTTPS para download de um ZIP. A identidade do pacote instalado AINDA DEVE corresponder a `author/name`. |
| `logo`              | string   | URL HTTPS de uma imagem ou caminho relativo de um recurso estático.                       |
| `tags`              | string[] | Lista de tags.                                                                             |
| `category`          | string   | Chave da categoria do mercado.                                                            |
| `support_platforms` | string[] | Chaves das plataformas compatíveis.                                                       |
| `astrbot_version`   | string   | Expressão de requisito de versão do AstrBot.                                               |
| `social_link`       | string   | URL HTTPS do autor ou do projeto.                                                          |
| `updated_at`        | string   | Data e hora no formato ISO 8601.                                                           |
| `i18n`              | object   | Campos de exibição localizados.                                                            |
| `pinned`            | boolean  | Indicador de recomendação do mercado.                                                      |
| `stars`             | integer  | Contagem não negativa de estrelas ou indicador de classificação.                          |
| `download_count`    | integer  | Contagem não negativa de downloads.                                                        |

### 7.1. URL do repositório

`repo` DEVE ser uma destas opções:

```text
https://github.com/{owner}/{repository}
https://github.com/{owner}/{repository}.git
https://github.com/{owner}/{repository}/tree/{branch}
```

`owner`, `repository` e `branch` DEVEM corresponder a:

```text
[A-Za-z0-9_-]+
```

`repo` NÃO DEVE ser:

- uma URL HTTP
- uma URL SSH
- uma URL que não seja do GitHub
- uma URL do GitHub Enterprise
- uma URL de arquivo, release, pull request, issue ou subdiretório do GitHub

`download_url` PODE apontar para qualquer URL HTTPS de um arquivo ZIP.

### 7.2. Campos localizados

Recomenda-se que as chaves de `i18n` sejam tags de localidade BCP 47.

Cada objeto de localidade PODE conter:

```json
{
  "display_name": "Nome localizado",
  "desc": "Descrição localizada",
  "short_desc": "Descrição curta localizada"
}
```

## 8. Campos reservados

As fontes do mercado NÃO DEVEM usar estes campos dentro de objetos `PluginRecord`:

| Campo                      | Motivo                                                                  |
| -------------------------- | ----------------------------------------------------------------------- |
| `plugin_id`                | Derivado de `author/name`.                                              |
| `market_plugin_id`         | Campo de compatibilidade do runtime/cliente, não é dado do mercado.    |
| `market_plugin_identifier` | Campo obsoleto de compatibilidade do runtime/cliente.                  |
| `root_dir_name`            | Campo de instalação local.                                              |
| `local_plugin_name`        | Campo de instalação local.                                              |
| `install_method`           | Campo de instalação local.                                              |
| `registry_url`             | Campo de instalação local.                                              |
| `registry_name`            | Campo de instalação local.                                              |
| `installed_at`             | Campo de instalação local.                                              |

Os consumidores NÃO DEVEM usar campos reservados para a identidade do plugin.

A chave raiz `$meta` é reservada para `MarketMetadata`.

## 9. Campos obsoletos

Estes campos PODEM ser aceitos pelos clientes durante a migração, mas novas fontes do mercado NÃO DEVEM emiti-los:

| Campo obsoleto    | Substituição         |
| ----------------- | -------------------- |
| `support_platform` | `support_platforms` |
| `platform`         | `support_platforms` |

## 10. Campos desconhecidos

Os consumidores PODEM preservar campos desconhecidos.

Os consumidores NÃO DEVEM usar campos desconhecidos para:

- identidade do plugin
- resolução da fonte de instalação
- resolução da fonte de atualização
- validação de segurança

## 11. Regras de validação

Uma fonte do mercado é válida somente se todas as regras forem atendidas:

1. O valor JSON raiz é um objeto.
2. `$meta` está presente.
3. `$meta` é um objeto.
4. `$meta.schema_version` é o inteiro `1`.
5. Cada chave raiz, exceto `$meta`, é uma chave `plugin_id` ou `name`.
6. Cada valor raiz, exceto `$meta`, é um objeto `PluginRecord`.
7. Cada registro contém todos os campos obrigatórios, exceto que `name` PODE ser omitido quando a chave raiz for uma chave `name`.
8. Cada campo de string obrigatório não fica vazio após a remoção de espaços em branco nas extremidades.
9. Os valores de `author` e de `name`, quando presente, não contêm `/`.
10. A chave raiz é exatamente igual a `${author}/${name}` ou, conforme a exceção de compatibilidade, é exatamente igual a `name`.
11. Nenhum par de IDs é igual após a normalização para minúsculas.
12. `repo` é uma URL HTTPS de um repositório GitHub.
13. Se presente, `download_url` é uma URL HTTPS.
14. Se presente, `tags` é um array de strings.
15. Se presente, `support_platforms` é um array de strings.
16. Se presente, `stars` é um inteiro não negativo.
17. Se presente, `download_count` é um inteiro não negativo.
18. Se presente, `updated_at` é uma data e hora no formato ISO 8601.
19. Se presente, `$meta.homepage` é uma URL HTTPS.
20. Se presente, `$meta.repository` é uma URL HTTPS.
21. Se presente, `$meta.updated_at` é uma data e hora no formato ISO 8601.
22. O pacote resolvido a partir de `repo` ou `download_url` contém `metadata.yaml`.
23. `metadata.yaml.author` é igual a `author`.
24. `metadata.yaml.name` é igual a `name`.
25. `metadata.yaml.version` é igual a `version`.

## 12. Regras de instalação

Para a instalação pelo mercado:

1. O cliente envia o `plugin_id` selecionado e a fonte do registro ao backend.
2. O backend resolve o `PluginRecord` a partir dessa fonte de registro usando `plugin_id`.
3. O backend instala usando `download_url`, quando disponível; caso contrário, instala usando `repo`.
4. Após a instalação, o backend lê o `metadata.yaml` instalado.
5. `metadata.yaml.author/name` do pacote instalado DEVE ser igual ao `plugin_id` selecionado.
6. Se a validação de identidade falhar, a instalação DEVE falhar.
7. Uma instalação bem-sucedida pelo mercado PODE persistir `repo`, `download_url`, informações do registro e horário da instalação no estado local.

## 13. Regras de atualização

Para plugins instalados pelo mercado:

1. As verificações de atualização DEVEM usar a fonte do registro armazenada no momento da instalação.
2. As verificações de atualização DEVEM resolver o registro do mercado por `plugin_id`.
3. A comparação de versões DEVE usar a versão dos metadados instalados e o campo `version` do registro do mercado.
4. A execução da atualização DEVE usar `repo/download_url` do registro do mercado resolvido.

Para instalações que não foram feitas pelo mercado:

1. Instalações por URL, Git e upload NÃO DEVEM ser tratadas como instalações do mercado.
2. Elas PODEM persistir `plugin_id` a partir do `metadata.yaml` instalado.
3. Elas NÃO DEVEM habilitar verificações de atualização do mercado, a menos que sejam explicitamente vinculadas a uma fonte do mercado.

## 14. Regras de vinculação da fonte

Ao vincular um plugin instalado fora do mercado a uma fonte do mercado:

1. A identidade do plugin instalado DEVE ser lida do `metadata.yaml` instalado.
2. Os registros candidatos do mercado DEVEM ter o mesmo `plugin_id`.
3. Recomenda-se que os registros candidatos do mercado tenham a mesma identidade de repositório.
4. A vinculação DEVE persistir a fonte de registro selecionada e o `plugin_id`.

## 15. Compatibilidade

Os consumidores PODEM ler fontes legadas do mercado durante a migração.

Para fontes legadas:

- Os consumidores PODEM aceitar fontes sem `$meta.schema_version` durante a migração.
- Recomenda-se que os consumidores construam `plugin_id` a partir de `author/name`.
- Recomenda-se que os consumidores rejeitem, para instalação pelo mercado, entradas sem `author` ou `name`.
- Os consumidores PODEM usar chaves raiz legadas somente para exibição.
- Os consumidores NÃO DEVEM usar chaves raiz legadas como identidade do plugin, a menos que a chave seja igual a `${author}/${name}`.

Novas fontes do mercado DEVEM incluir `$meta.schema_version`.
